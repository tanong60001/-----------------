## ฝั่ง Supabase ที่ยังต้องตรวจ

Supabase CLI บนเครื่องนี้ไม่มี access token และไม่มีแท็บเบราว์เซอร์ที่เชื่อมต่อให้ควบคุม
จึงยังไม่ได้อ่านค่าปัจจุบันหรือเปลี่ยนการตั้งค่า log ของฐานข้อมูล
รัน SQL อ่านอย่างเดียวนี้ใน SQL Editor ของโปรเจกต์ pos เพื่อระบุแหล่ง log ก่อนปรับ:

```sql
select name, setting, unit, source, pending_restart
from pg_settings
where name in (
  'log_statement', 'log_duration', 'log_min_duration_statement',
  'log_min_messages', 'log_min_error_statement',
  'log_connections', 'log_disconnections',
  'log_autovacuum_min_duration', 'log_temp_files', 'log_lock_waits',
  'pgaudit.log', 'pgaudit.role', 'cron.log_statement'
)
order by name;

select rolname, rolconfig
from pg_roles
where rolname in ('postgres', 'authenticator', 'anon', 'authenticated', 'service_role');
```

ตาม [เอกสาร Supabase](https://supabase.com/docs/guides/platform/manage-your-usage/logs-ingest)
ควรตรวจ `log_statement`, slow-query threshold และ pgAudit เป็นอันดับแรก
ลดระดับ debug/verbose ที่เปิดทิ้งไว้ โดยรักษา error และข้อมูลที่ใช้วิเคราะห์ปัญหา
การบันทึก log ของแต่ละบริการและจำนวนคำขอจริงยังมีผลต่อยอดรวม
จึงต้องตรวจอัตราเพิ่มใน Usage หลังใช้เวอร์ชันใหม่ 24–48 ชั่วโมง จึงจะประเมินได้ว่าจะต่ำกว่า 1 GB ต่อรอบหรือไม่

การตั้งค่าที่แก้ได้และช่องทาง SQL/CLI/API แตกต่างกัน ดู
[Postgres log configuration](https://supabase.com/docs/guides/database/postgres/postgres-log-config)
ก่อนปรับ ไม่จำเป็นต้องลบข้อมูลธุรกรรมหรือประวัติกิจกรรมเพื่อแก้งานนี้
