# คู่มือติดตั้งและใช้งาน LINE ผู้ช่วยร้าน

ระบบนี้ใช้ Edge Function ที่ใช้งานจริงอยู่แล้วเพียง 2 ตัว:

- `line-attendance-report` เป็น LINE Webhook, เมนูผู้ช่วย และรายงานเช็คชื่อ/ลูกหนี้/ขนส่ง/สินค้าขายดี
- `line-cashdrawer` แจ้งเปิด-ปิดลิ้นชักเหมือนเดิม และสร้างรายงานยอดขาย/จำนวนแบงค์ให้ผู้ช่วย

ระบบเน้นกดดูเพื่อประหยัดโควต้า LINE:

- ปิดการแจ้งเช็คชื่ออัตโนมัติตอนเช้า
- ปิดสรุปยอดขายอัตโนมัติตอนเย็น
- ปิดการ์ดเปิด/ปิดลิ้นชักอัตโนมัติ โดยข้อมูลลิ้นชักยังกดดูจากเมนูได้
- รายงานทั้ง 6 รายการเรียกดูได้จากเมนูผู้ช่วย

## หน้าตาการใช้งาน

ในกลุ่ม LINE ที่มีบอท พิมพ์คำใดคำหนึ่ง:

```text
สวัดดีผู้ช่วย
สวัสดีผู้ช่วย
สวัดดี
สวัสดี
ผู้ช่วย
เมนูผู้ช่วย
```

บอทจะแสดงการ์ด “สวัสดีครับ ผมคือผู้ช่วยร้าน” พร้อม 6 ตัวเลือก:

1. เช็คชื่อวันนี้
2. ยอดขายวันนี้
3. จำนวนแบงค์ในลิ้นชัก
4. ลูกค้าค้างชำระทั้งหมด
5. รายการขนส่ง
6. สินค้าขายดี 30 วัน

เมนูแสดงเป็นตาราง 2 คอลัมน์แบบสั้นและเลือกสะสมได้หลายหัวข้อ:

- แตะหัวข้อเพื่อเลือก แล้ว LINE จะแสดงข้อความฝั่งผู้ใช้ `✅ เลือก: ...` เพื่อยืนยันสถานะ
- ข้อความยืนยันเป็นข้อความฝั่งผู้ใช้ บอทไม่ส่งเมนูใบใหม่และไม่ใช้โควต้าขาออกเพิ่ม
- แตะรายการเดิมซ้ำจะไม่เพิ่มข้อมูลซ้ำ หากต้องการเริ่มใหม่ให้กดล้างตัวเลือก
- เลือกครบแล้วกด `ดูรายงานที่เลือก`
- รายงานทั้งหมดส่งเป็น Flex Message เพียง 1 ข้อความ และเลื่อนการ์ดซ้าย-ขวาได้
- ปุ่ม `ล้างตัวเลือก` ล้างสถานะแบบเงียบ ๆ ไม่ส่งข้อความตอบ
- ต้องการเปิดเมนูใหม่ให้พิมพ์ `ผู้ช่วย`

สถานะตัวเลือกเก็บเป็นไฟล์ JSON ขนาดเล็กใน Supabase Storage และล้างหลังส่งรายงาน ไม่ต้องสร้างตารางเพิ่ม

## ความหมายของข้อมูลแต่ละรายงาน

### 1. เช็คชื่อวันนี้

- แสดงจำนวน มา / มาสาย / ครึ่งวัน / ลา / ขาด
- ถ้ายังไม่มีใครลงข้อมูล จะแจ้ง `ยังไม่มีการอัปเดตเช็คชื่อวันนี้`
- ถ้าลงไม่ครบ จะแสดงรายชื่อผู้ที่ยังไม่มีข้อมูล
- ถ้าครบแล้ว จะแจ้ง `อัปเดตครบทุกคนแล้ว`

### 2. ยอดขายวันนี้

- เริ่มนับจาก `cash_session.opened_at` ของรอบลิ้นชักที่กำลังเปิด
- แสดงยอดรวม จำนวนบิล และบิลล่าสุด
- แยกยอดเงินสด เงินโอน บัตร และวิธีอื่น
- บิล `เงินโอน+เงินสด` จะแยกส่วนเงินสดจาก `cash_transaction` และนำยอดที่เหลือไปรวมเงินโอน
- ไม่นับบิลยกเลิก คืนสินค้า หนี้เสีย และตัดหนี้
- ถ้ายังไม่เปิดรอบลิ้นชัก จะแจ้งให้ทราบแทนการเดายอด

### 3. จำนวนแบงค์ในลิ้นชัก

คำนวณตามวิธีเดียวกับหน้าลิ้นชัก:

```text
จำนวนยอดเปิด
+ ธนบัตร/เหรียญที่รับเข้า
- ธนบัตร/เหรียญที่จ่ายออก
- เงินทอนของรายการรับเข้า
+ เงินทอนคืนของรายการจ่ายออก
```

แสดงแยกทุกชนิดตั้งแต่ 1,000 บาทถึง 25 สตางค์ หากชนิดใดติดลบ ระบบจะแจ้งให้ตรวจนับเงินจริง

### 4. ลูกค้าค้างชำระทั้งหมด

- อ่านยอด `customer.debt_amount` ปัจจุบัน
- เรียงจากยอดค้างสูงสุด
- แสดงยอดรวม จำนวนลูกค้า และรายละเอียด 6 รายแรก
- รายการที่บันทึกเป็นหนี้เสียถูกระบบหน้าลูกหนี้ย้ายออกจากยอดนี้แล้ว จึงไม่รวมทะเบียนหนี้เสีย

### 5. รายการขนส่ง

- แสดงเฉพาะงานจัดส่งที่ยังไม่สำเร็จ
- แยก เกินกำหนด / ส่งวันนี้ / งานถัดไป / ยังไม่กำหนดวัน
- แสดงบิล ลูกค้า วันนัด และยอดที่ต้องเก็บ
- ไม่นับบิลยกเลิก คืนสินค้า รับเอง และงานที่ส่งสำเร็จแล้ว

### 6. สินค้าขายดี 30 วัน

- อ่านบิลย้อนหลัง 30 วันและรายการสินค้าในบิลจริง
- เรียงตามยอดขายเป็นจำนวนเงินจากมากไปน้อย
- สร้างรายงาน PDF สูงสุด 100 อันดับ พร้อมยอดเงิน จำนวน และหน่วยที่ขาย
- PDF จัดเป็นตารางหลายหน้า ใช้ฟอนต์ภาษาไทย และเรียงตามยอดขายเป็นเงิน
- LINE ส่งเพียงการ์ดสรุปสั้นพร้อมปุ่มเปิด/ดาวน์โหลด PDF
- ไฟล์อยู่ใน Storage แบบ private และลิงก์ดาวน์โหลดมีอายุ 7 วัน
- ไม่นับบิลยกเลิก คืนสินค้า หนี้เสีย และตัดหนี้

## การติดตั้ง

เปิด PowerShell หรือ Command Prompt ที่โฟลเดอร์โปรแกรม:

```powershell
cd "C:\Users\OMEN\Desktop\โปรแกรมร้าน"
```

ติดตั้งและล็อกอิน Supabase CLI หากเครื่องยังไม่มี:

```powershell
npm install -g supabase
supabase login
supabase link --project-ref thfswrvnyhuqmdazjfhd
```

ตั้ง Secret ที่จำเป็น:

```powershell
supabase secrets set LINE_TOKEN="Channel access token ตัวจริง"
supabase secrets set LINE_CHANNEL_SECRET="Channel secret ตัวจริง"
supabase secrets set LINE_GROUP_ID="Cxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
```

`SUPABASE_URL` และ `SUPABASE_SERVICE_ROLE_KEY` มีให้อัตโนมัติใน Supabase Edge Functions ไม่ต้องคัดลอก service role key ไปไว้ในหน้าเว็บ

Deploy ตามลำดับนี้ เพราะฟังก์ชันเมนูจะเรียกฟังก์ชันลิ้นชัก:

```powershell
supabase functions deploy line-cashdrawer --no-verify-jwt
supabase functions deploy line-attendance-report --no-verify-jwt
supabase functions deploy line-daily-summary --no-verify-jwt
```

บรรทัด `line-daily-summary` ใช้ติดตั้งตัวป้องกันไม่ให้ cron เดิมส่งสรุปตอนเย็น หากลบ cron เรียบร้อยแล้ว ฟังก์ชันนี้จะไม่มีการเรียกใช้งานเพิ่มเติม

ต้องมี `--no-verify-jwt` เพราะ LINE ส่ง webhook ด้วยลายเซ็น `x-line-signature` ไม่ได้ส่ง Supabase JWT ส่วนโค้ดจะตรวจลายเซ็น LINE ด้วย `LINE_CHANNEL_SECRET` ก่อนอ่านข้อมูลร้าน

## ตั้งค่า LINE Developers

ไปที่ LINE Developers Console > Messaging API ของ Channel ร้าน:

1. ตั้ง Webhook URL เป็น:

   ```text
   https://thfswrvnyhuqmdazjfhd.supabase.co/functions/v1/line-attendance-report
   ```

2. กด `Verify` ต้องขึ้น Success
3. เปิด `Use webhook`
4. ปิด Auto-reply messages ใน LINE Official Account Manager เพื่อไม่ให้คำตอบซ้ำ
5. เชิญบอทเข้ากลุ่มที่มี ID ตรงกับ `LINE_GROUP_ID`

LINE Channel มี Webhook URL หลักได้ตัวเดียว จึงใช้ `line-attendance-report` เป็นทางเข้าแทน `line-webhook` ตัวเก่า ส่วน `line-cashdrawer` ถูกเรียกภายในอย่างปลอดภัยและยังรับแจ้งเปิด/ปิดจากหน้าโปรแกรมตามเดิม

## ปิดงานอัตโนมัติเพื่อประหยัดโควต้า

โค้ดจะไม่ส่งเช็คชื่อและสรุปยอดขายอัตโนมัติ แม้ Database Webhook หรือ cron เดิมยังเรียกอยู่ แต่แนะนำให้ลบงานที่ไม่จำเป็นด้วย:

### Database Webhook เช็คชื่อ

Supabase Dashboard > Database > Webhooks:

- ลบหรือปิด Webhook ที่ชี้ตาราง `เช็คชื่อ` ไปยัง `line-attendance-report`

### cron สรุปยอดขายตอนเย็น

เปิด SQL Editor แล้วตรวจชื่องาน:

```sql
select jobid, jobname, schedule, active
from cron.job
where jobname = 'line-daily-summary';
```

ลบงานสรุปตอนเย็น:

```sql
select cron.unschedule('line-daily-summary');
```

ฟังก์ชัน `line-daily-summary` ถูกตั้งให้ไม่ส่งข้อความเป็นค่าเริ่มต้นด้วย หากต้องการเปิดกลับในอนาคตต้องตั้ง `ENABLE_LINE_SCHEDULED_PUSH=true` อย่างชัดเจน

ฟังก์ชัน `line-cashdrawer` ถูกตั้งให้ไม่ส่งการ์ดเปิด/ปิดลิ้นชักเป็นค่าเริ่มต้นด้วย หากต้องการเปิดกลับในอนาคตต้องตั้ง `ENABLE_LINE_CASHDRAWER_PUSH=true`

## ทดสอบหลังติดตั้ง

1. เปิดรอบลิ้นชักในโปรแกรมและตรวจว่าการ์ดเปิดลิ้นชักยังเข้ากลุ่ม
2. สร้างบิลทดสอบ 1 บิลแบบเงินสดหรือโอน
3. ในกลุ่ม LINE พิมพ์ `สวัดดีผู้ช่วย`
4. เลือกข้อ 2 และ 3 แล้วกดแสดงรายงาน
5. ตรวจเวลาเริ่มรอบ ยอดบิล วิธีชำระ และจำนวนแบงค์
6. ทดสอบเลือกทั้ง 6 ข้อพร้อมกันและเลื่อนการ์ดซ้าย-ขวา
7. ทดสอบเช็คชื่อแบบยังไม่ครบ เพื่อดูรายชื่อผู้ที่ยังไม่อัปเดต

## แก้ปัญหาเบื้องต้น

### พิมพ์แล้วบอทเงียบ

- ตรวจว่า Use webhook เปิดอยู่
- ตรวจ Webhook URL ว่าชี้ `line-attendance-report`
- ตรวจ `LINE_GROUP_ID` ว่าเป็นกลุ่มเดียวกับที่กำลังพิมพ์
- ตรวจว่าพิมพ์หนึ่งในคำเรียกที่รองรับ

### Verify ขึ้น 401 invalid signature

- `LINE_CHANNEL_SECRET` ไม่ตรงกับ Channel ที่ใช้
- ตั้ง Secret ใหม่แล้ว deploy `line-attendance-report` ซ้ำ

### ยอดขายแจ้งว่ายังไม่เปิดรอบ

- ต้องเปิดลิ้นชักในหน้าโปรแกรมก่อน
- รายงานนี้ตั้งใจนับจากเวลาเปิดรอบ ไม่ได้นับตั้งแต่เที่ยงคืน

### จำนวนแบงค์ติดลบ

- มีรายการขายที่ไม่ได้บันทึกแบงค์รับ/เงินทอนครบ
- มีการเบิก/แลกเงินที่จำนวนแบงค์เข้าออกไม่ตรงกัน
- ให้นับเงินจริงและตรวจรายการลิ้นชักในโปรแกรม

### รายงานบางการ์ดขึ้นโหลดไม่สำเร็จ

- การ์ดอื่นจะยังแสดงได้ตามปกติ
- เปิด Supabase Dashboard > Edge Functions > Logs
- ดู log ของ `line-attendance-report` และ `line-cashdrawer`
- ตรวจว่าตาราง/คอลัมน์ของฐานข้อมูลตรงกับเวอร์ชันโปรแกรมล่าสุด
